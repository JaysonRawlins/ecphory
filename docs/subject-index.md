# Subject index

Render a workspace's recall keys into the instruction file each agent harness
already reads, so every agent on a repo knows *what to ask ecphory for*.

## The gap this closes

ecphory is the shared store, but only one harness finds its way in unaided.
Claude Code injects a per-project `MEMORY.md` as a first-class instruction
source (attachment type `AutoMem`). That file is a slim index of search keys,
and it is what makes recall work: an agent holding the index knows what to
search for. Without it ecphory is still reachable and still returns good
results, but the agent never asks the questions.

Codex, agy and opencode read `AGENTS.md`. They get the same MCP access and
none of the index, so on the same repo they start materially behind.

`ecphory render-index` writes the index into both.

## Scoping: the `ws:` tag

An episode joins a workspace's index by carrying the tag `ws:<slug>`:

```
$ ecphory workspace-key
ws:-Users-me-code-myrepo
```

Tag the episode with that when you store it, and it appears in that
workspace's index. Tags, not `group_id`, because an episode can belong to two
workspaces (a cross-repo lesson does), and because tagging is additive — no
migration, and existing episodes join by having a tag added.

The slug is Claude Code's own project-directory rule (every character outside
`[A-Za-z0-9]` becomes `-`; past 200 characters, truncate and append a base36
hash of the original path), applied to the **git toplevel**, falling back to
the working directory when there is no repo. Deliberately the same rule Claude
uses, so the two agree on what "this project" means rather than drifting.

**Linked worktrees resolve to the main checkout.** The key comes from
`git rev-parse --git-common-dir`, which in a worktree points at the main
repository's `.git`. An agent launched in `~/worktrees/feature-x` and one
launched in the main checkout read the same index:

```
$ ecphory workspace-key --workspace ~/agent-worktrees/ecphory/issue-24
ws:-Users-me-code-GitHub-me-ecphory
$ ecphory workspace-key --workspace ~/code/GitHub/me/ecphory
ws:-Users-me-code-GitHub-me-ecphory
```

## Rendering

```
ecphory render-index [--workspace <dir>] [--url <base>] [--out <file>]... [--check]
```

| Flag | Meaning |
|---|---|
| `--workspace` | Directory to scope to (default: the current one), resolved to its git toplevel. |
| `--url` | Daemon base URL. Global flag: `--url`, then `$ECPHORY_URL`, then `http://127.0.0.1:3491`. |
| `--out` | Output file, repeatable. Replaces the default targets entirely. |
| `--check` | Print stale targets and exit 1. Writes nothing. |

Default targets:

- `<workspace>/AGENTS.md` — codex, agy, opencode.
- `$CLAUDE_CONFIG_DIR/projects/<slug>/memory/MEMORY.md` (or `~/.claude/...`) —
  Claude Code. If you have moved the memory directory (`autoMemoryDirectory`,
  `CLAUDE_COWORK_MEMORY_PATH_OVERRIDE`, `CLAUDE_CODE_REMOTE_MEMORY_DIR`), name
  the target with `--out` instead; the default only follows `CLAUDE_CONFIG_DIR`.

The tag filter is applied twice on purpose: server-side by `?tags=`, and again
when the rows are built. A daemon older than this feature ignores the query
parameter and returns everything, so the second pass is what keeps the output
correct — a stale daemon degrades to wasteful, not wrong.

**It reads over HTTP, never the database.** The daemon holds redb's
process-exclusive lock, so a render that opened the store directly would fail
every time it mattered — including from a post-write trigger, which is exactly
when it runs. Same reason `eval` is HTTP-only. Observed on 0.3.5:

```
$ ecphory --db <live db> list --limit 1
Error: storage error: Database already open. Cannot acquire lock.
$ ecphory render-index --url http://127.0.0.1:3491 --out /tmp/OUT.md
wrote /tmp/OUT.md (14 keys for ws:-Users-me-code-myrepo)
```

## What lands in the file

Keys only — query phrase, tags, one-line description, episode id. Never
episode bodies. The file is a pointer; ecphory holds the content. That is what
keeps the block small enough to sit in every session, and it is asserted by a
test that fails if any body text reaches the output.

Row material comes from the episode's `search_phrases` (the query — they are
already written as "how someone would ask for this") and its `name` (the
description). An episode with neither is skipped: a row with no query points
nowhere. The workspace tag itself is dropped from the tag column, being
identical on every row.

Output goes inside a marked region:

```markdown
# House rules

Run the tests before pushing.

<!-- BEGIN ecphory subject index -->
<!-- GENERATED by `ecphory render-index` — DO NOT HAND-EDIT.
     Recall keys for `ws:-Users-me-code-myrepo`. Keys only: the content lives in ecphory.
     Search the Query text (MCP `search`, or `ecphory search "<query>"`),
     then read the episode by its id. -->

| Query | Tags | Description | Episode |
| --- | --- | --- | --- |
| why does the CLI hang while the daemon is up | gotcha | the redb lock incident | 019f… |
<!-- END ecphory subject index -->
```

Everything outside the markers is preserved byte for byte, so a hand-written
`AGENTS.md` survives regeneration. A file with only one marker, or with `END`
before `BEGIN`, is an error rather than a guess — any choice there risks eating
someone's text. Rendering is deterministic and the file is only written when
the bytes change, so a no-op render produces no diff and no mtime churn.

### `AGENTS.md` is a tracked file

It is, and this writes generated content into it. The alternative — a separate
gitignored file — only works if the harness follows includes, and codex, agy
and opencode do not guarantee that, so it would defeat the purpose. The
mitigations are the marked region (hand-written content survives) and
write-if-changed (an unchanged index is not a diff). If you would rather it
stayed out of a shared repo's history, point `--out` somewhere else — the
default is a convention, not a requirement.

## Keeping it fresh: the trigger seam

[Post-write triggers](triggers.md) already run a local command when a matching
episode changes. The index is a render target on that, not new machinery. One
trigger per workspace, matching that workspace's tag:

```json
{
  "triggers": [
    {
      "name": "render-index-myrepo",
      "events": ["insert", "update", "demote", "restore", "restore_version"],
      "match": { "tags_any": ["ws:-Users-me-code-myrepo"] },
      "run": [
        "/usr/local/bin/ecphory", "render-index",
        "--workspace", "/Users/me/code/myrepo",
        "--url", "http://127.0.0.1:3491"
      ],
      "timeout_seconds": 60
    }
  ]
}
```

`insert` and `demote` are worth naming explicitly here: unlike a
single-episode render, an index changes when an episode *joins or leaves* it,
not only when one is edited.

`--check` exits 1 when a target is stale, which is the shape a pre-commit hook
or a CI job wants.
